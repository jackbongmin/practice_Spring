## 0. 먼저 알아둘 것

### 값은 세 곳으로 들어온다

| 위치 | 예 | 받는 법 | 주로 쓰는 메서드 |
| :--- | :--- | :--- | :--- |
| **path** | `/members/3` | `@PathVariable` | GET, PUT, DELETE (대상 지정) |
| **query** | `?name=kim&age=3` | `@RequestParam` / DTO | GET (검색·필터) |
| **body** | `{"name":"kim"}` | `@RequestBody` | POST, PUT (데이터 본체) |

### HTTP 메서드의 의미

| 메서드 | 의미 | 성공 시 보통 |
| :-: | :--- | :--- |
| GET | 조회 | `200` |
| POST | 생성 | `201 Created` |
| PUT | 수정(전체 교체) | `200` |
| DELETE | 삭제 | `204 No Content` |

### 받는 방식 3종 비교 (GET의 핵심)

| 방식 | 선언 | key 제한 | 값이 빠지면 |
| :--- | :--- | :--- | :--- |
| 개별 | `@RequestParam String name` | 선언한 key만 | **400** |
| Map | `@RequestParam Map<String,String>` | 없음 (뭐든 통과) | 해당 없음 |
| DTO | `MemberDto dto` | 필드명이 계약 | **400 아님, `null`** |

### 상태코드 읽기

| 코드 | 의미 | 흔한 원인 |
| :-: | :--- | :--- |
| 200 / 201 / 204 | 성공 / 생성 / 본문 없음 | 정상 |
| 400 | 요청이 잘못됨 | 필수 param 누락, 깨진 JSON, 검증 실패 |
| 404 | 대상 없음 | 경로 오타, 없는 id |
| 405 | 메서드 불일치 | GET으로 POST 경로 호출 |
| 415 | Content-Type 불일치 | POST에 `application/json` 헤더 누락 |
| 500 | 서버 코드 오류 | 예외 미처리 |

## Step 3: GET

`controller/GetController.java`

```java
package org.example.practice_spring.day03_api.controller;

import java.util.Map;
import lombok.extern.slf4j.Slf4j;
import org.example.practice_spring.day03_api.dto.MemberDto;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

/**
 * GET 요청에서 값을 받는 3가지 방식(path / query 개별 / query DTO)을 비교하는 연습용 컨트롤러.
 * - 클래스에 붙인 @RequestMapping 은 모든 메서드 경로의 공통 앞부분이 된다.
 */
@Slf4j
@RestController
@RequestMapping("/api/v1/get-api")
public class GetController {

    // GET /api/v1/get-api/hello -> Hello World
    @GetMapping("/hello")
    public String hello() {
        log.info("hello 호출");
        return "Hello World";
    }

    // GET /api/v1/get-api/variable/test -> test   (path 값)
    @GetMapping("/variable/{variable}")
    public String variable(@PathVariable String variable) {
        log.info("path 로 들어온 값 : {}", variable);
        return variable;
    }

    // GET /api/v1/get-api/request1?name=kim&email=k@x.com&organization=kyobo
    // 개별 @RequestParam 은 기본이 필수 -> 하나라도 빠지면 400
    @GetMapping("/request1")
    public String request1(@RequestParam String name,
                           @RequestParam String email,
                           @RequestParam String organization) {
        return name + " " + email + " " + organization;
    }

    // GET /api/v1/get-api/request2?a=1&b=2
    // Map 은 key 제한이 없다 -> 무슨 key 가 와도 통과
    @GetMapping("/request2")
    public String request2(@RequestParam Map<String, String> param) {
        StringBuilder sb = new StringBuilder();
        param.forEach((k, v) -> sb.append(k).append(" : ").append(v).append("\n"));
        return sb.toString();
    }

    // GET /api/v1/get-api/request3?name=kim&email=k@x.com   (organization 생략)
    // DTO 는 필드명이 계약 -> 빠진 값은 400 이 아니라 null
    @GetMapping("/request3")
    public String request3(MemberDto memberDto) {
        return memberDto.toString();
    }
}
```

**실행 후 예측 → 확인** (브라우저 주소창, 서버 `8080`)

| 요청 | 예상 |
| :--- | :--- |
| `/api/v1/get-api/variable/test` | `test` |
| `/api/v1/get-api/request1?name=kim&email=k@x.com&organization=kyobo` | `kim k@x.com kyobo` |
| `/api/v1/get-api/request1?name=kim&email=k@x.com` | **400** |
| `/api/v1/get-api/request2?a=1&b=2` | `a : 1` `b : 2` (줄바꿈은 브라우저에서 한 줄로 보임) |
| `/api/v1/get-api/request3?name=kim&email=k@x.com` | `MemberDto[name=kim, email=k@x.com, organization=null]` |

> `hello`, `variable` 호출 시 IntelliJ 콘솔에 `log.info` 가 찍힙니다. 응답에는 안 보이고 **서버 로그에만** 남는 정보입니다.

## Step 4: POST

`controller/PostController.java`

```java
package org.example.practice_spring.day03_api.controller;

import java.util.Map;
import org.example.practice_spring.day03_api.dto.MemberDto;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/**
 * POST 는 값을 URL 이 아니라 요청 body(JSON)에 담아 보낸다.
 * - 요청에 Content-Type: application/json 헤더가 있어야 @RequestBody 가 JSON 으로 읽는다.
 */
@RestController
@RequestMapping("/api/v1/post-api")
public class PostController {

    // POST /api/v1/post-api/member  (Map: 어떤 key 든 받는다)
    @PostMapping("/member")
    public String member(@RequestBody Map<String, Object> body) {
        StringBuilder sb = new StringBuilder();
        body.forEach((k, v) -> sb.append(k).append(" : ").append(v).append("\n"));
        return sb.toString();
    }

    // POST /api/v1/post-api/member2  (DTO: 필드명이 계약)
    @PostMapping("/member2")
    public String memberDto(@RequestBody MemberDto memberDto) {
        return memberDto.toString();
    }
}
```

주소창은 GET만 보낼 수 있으므로 `curl`(Step 8) 또는 IntelliJ HTTP Client를 씁니다.

```bash
curl -i -X POST http://localhost:8080/api/v1/post-api/member2 \
  -H "Content-Type: application/json" \
  -d '{"name":"kim","email":"k@x.com","organization":"kyobo"}'
```

**오류 3종 — 보내기 전에 몇 번대 코드일지 예측**

| 요청 | 결과 | 이유 |
| :--- | :-: | :--- |
| `-H` Content-Type 생략 | **415** | 서버가 JSON으로 읽을 근거가 없음 |
| 중괄호 하나 뺀 깨진 JSON | **400** | body를 읽는 단계에서 실패 |
| `organization` 대신 `org` | **200** | 읽기는 성공, 이름이 안 맞아 `organization=null` (**조용히 틀림**) |

```java
package org.example.practice_spring.day03_api.controller;

import org.example.practice_spring.day03_api.dto.MemberDto;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/**
 * 반환 타입에 따라 응답이 어떻게 달라지는지 보는 PUT 연습용 컨트롤러.
 * - String            -> 글자 그대로 (200)
 * - MemberDto         -> JSON 으로 자동 변환 (200)
 * - ResponseEntity<T> -> status / header / body 를 직접 지정
 */
@RestController
@RequestMapping("/api/v1/put-api")
public class PutController {

    @PutMapping("/member1")
    public String asString(@RequestBody MemberDto dto) {
        return dto.toString();
    }

    @PutMapping("/member2")
    public MemberDto asJson(@RequestBody MemberDto dto) {
        return dto;
    }

    // 200 이 아닌 202 Accepted 로 응답
    @PutMapping("/member3")
    public ResponseEntity<MemberDto> asEntity(@RequestBody MemberDto dto) {
        return ResponseEntity.status(HttpStatus.ACCEPTED).body(dto);
    }
}
```

## Step 6: 회원 CRUD

Step 3~5는 "받는 법" 연습이었고, 여기서는 **한 자원(회원)을 URL 하나 + 메서드 4개로 다루는** 실전 모양으로 만듭니다.
추가로 ① 요청/응답 DTO 분리 ② 입력 검증 ③ 상태코드 의미화 ④ 오류 응답 통일을 적용합니다.

| 요청 | 성공 | 실패 |
| :--- | :-: | :-: |
| `GET    /api/v1/members` | 200 배열 | |
| `GET    /api/v1/members/{id}` | 200 | 404 |
| `POST   /api/v1/members` | **201** + `Location` | 400 (검증) |
| `PUT    /api/v1/members/{id}` | 200 | 400 / 404 |
| `DELETE /api/v1/members/{id}` | **204** | 404 |

`repository/MemberRepository.java`

```java
package org.example.practice_spring.day03_api.repository;

import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicLong;
import org.example.practice_spring.day03_api.dto.MemberRequest;
import org.example.practice_spring.day03_api.dto.MemberResponse;
import org.springframework.stereotype.Repository;

/**
 * DB 대신 메모리(Map)에 회원을 저장하는 저장소.
 * - 아직 DB 를 배우지 않았으므로 "저장 -> 조회로 확인" 흐름만 체험하기 위한 임시 구현이다.
 * - 서버를 재시작하면 데이터가 사라진다. 나중에 JPA 로 교체해도 컨트롤러가 거의 안 바뀌게 메서드를 단순하게 둔다.
 */
@Repository
public class MemberRepository {

    private final Map<Long, MemberResponse> store = new ConcurrentHashMap<>();
    private final AtomicLong sequence = new AtomicLong();   // id 자동 발급기 (1, 2, 3 ...)

    public MemberResponse save(MemberRequest r) {
        long id = sequence.incrementAndGet();
        MemberResponse saved = new MemberResponse(id, r.name(), r.email(), r.organization());
        store.put(id, saved);
        return saved;
    }

    public Optional<MemberResponse> findById(Long id) {
        return Optional.ofNullable(store.get(id));
    }

    public List<MemberResponse> findAll() {
        return new ArrayList<>(store.values());
    }

    public Optional<MemberResponse> update(Long id, MemberRequest r) {
        if (!store.containsKey(id)) {
            return Optional.empty();
        }
        MemberResponse updated = new MemberResponse(id, r.name(), r.email(), r.organization());
        store.put(id, updated);
        return Optional.of(updated);
    }

    public boolean delete(Long id) {
        return store.remove(id) != null;
    }
}
```

`exception/ApiExceptionHandler.java`

```java
package org.example.practice_spring.day03_api.exception;

import org.example.practice_spring.day03_api.dto.ErrorResponse;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

/**
 * 컨트롤러에서 던져진 예외를 한곳에서 받아 "상태코드 + 통일된 JSON" 으로 바꾸는 전역 처리기.
 * - 컨트롤러마다 try/catch 를 쓰지 않아도 되게 하려고 만든다.
 */
@RestControllerAdvice
public class ApiExceptionHandler {

    // 없는 id 조회/수정/삭제 -> 404
    @ExceptionHandler(MemberNotFoundException.class)
    public ResponseEntity<ErrorResponse> notFound(MemberNotFoundException e) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
                .body(new ErrorResponse(404, e.getMessage()));
    }

    // @Valid 검증 실패 -> 400 (실패한 필드의 첫 메시지를 담는다)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> invalid(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().get(0).getDefaultMessage();
        return ResponseEntity.badRequest().body(new ErrorResponse(400, message));
    }
}
```

```java
import lombok.RequiredArgsConstructor;
import org.example.practice_spring.day03_api.dto.MemberRequest;
import org.example.practice_spring.day03_api.dto.MemberResponse;
import org.example.practice_spring.day03_api.exception.MemberNotFoundException;
import org.example.practice_spring.day03_api.repository.MemberRepository;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/**
 * 오늘 배운 GET/POST/PUT/DELETE 를 "회원"이라는 하나의 자원에 모아 만든 REST CRUD API.
 * - 같은 URL(/api/v1/members)을 HTTP 메서드로 구분한다: 목록(GET) / 등록(POST) / 수정(PUT) / 삭제(DELETE)
 * - 상태코드까지 의미 있게 돌려주는 것이 앞의 연습용 컨트롤러와의 차이다.
 */
@RestController
@RequestMapping("/api/v1/members")
@RequiredArgsConstructor
public class MemberController {

    private final MemberRepository repository;

    // 200 + 배열
    @GetMapping
    public List<MemberResponse> list() {
        return repository.findAll();
    }

    // 200 + 객체 / 없으면 404
    @GetMapping("/{id}")
    public MemberResponse get(@PathVariable Long id) {
        return repository.findById(id).orElseThrow(() -> new MemberNotFoundException(id));
    }

    // 201 Created + Location 헤더 + 만들어진 객체
    @PostMapping
    public ResponseEntity<MemberResponse> create(@Valid @RequestBody MemberRequest request) {
        MemberResponse saved = repository.save(request);
        return ResponseEntity.created(URI.create("/api/v1/members/" + saved.id())).body(saved);
    }

    // 200 + 수정된 객체 / 없으면 404
    @PutMapping("/{id}")
    public MemberResponse update(@PathVariable Long id, @Valid @RequestBody MemberRequest request) {
        return repository.update(id, request).orElseThrow(() -> new MemberNotFoundException(id));
    }

    // 204 No Content (본문 없음) / 없으면 404
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> delete(@PathVariable Long id) {
        if (!repository.delete(id)) {
            throw new MemberNotFoundException(id);
        }
        return ResponseEntity.noContent().build();
    }
}
```

## Step 8: curl 호출 모음 + 7단계 검증표

서버를 띄운 뒤 (`-i` 는 status/header 출력). Windows 에서는 `curl.exe` 를 쓰고, JSON의 `"` 는 Git Bash 에서 실행하는 걸 권장합니다.

```bash
# 등록 -> 201 + Location

  -d '{"name":"kim","email":"k@x.com","organization":"kyobo"}'

# 목록 / 단건

curl -i localhost:8080/api/v1/members/1

curl -i -X DELETE localhost:8080/api/v1/members/1
curl -i localhost:8080/api/v1/members/1
```

### 요청이 안 될 때: 위에서 아래로 7단계 점검

| # | 확인 | 어긋나면 고칠 곳 |
| :-: | :--- | :--- |
| ① method | `@GetMapping` / `@PostMapping` … 과 호출 메서드가 같은가 | 405 → 요청 or 매핑 |
| ② path | 클래스 `@RequestMapping` + 메서드 매핑을 이어 붙인 주소가 맞는가 | 404 → 요청 |
| ③ 입력 위치 | path / query / body 중 코드가 기대하는 곳에 보냈나 | 요청 |
| ④ key / field | key 이름이 매개변수·필드명과 정확히 같은가 | 요청 (틀려도 `null`로 조용히 통과) |
| ⑤ Content-Type | body 요청에 `application/json` 이 있는가 | 415 → 요청 |
| ⑥ status | 기대한 코드(201, 204 …)가 나왔는가 | 코드 (`ResponseEntity`) |
| ⑦ body | 응답 모양이 기대와 같은가 | 코드 (반환 타입 / DTO) |
| ⑧ 부작용 | **PUT/DELETE 후 GET으로 실제 변경을 확인했나** | 코드 (저장소 로직) |

## 자주 겪는 오류

| 증상 | 원인 | 해결 |
| :--- | :--- | :--- |
| `404` | 클래스 경로를 빼먹고 호출 (`/hello` 만 호출) | ② 클래스 + 메서드 경로를 이어 붙이기 |
| `400` Required request parameter … | 개별 `@RequestParam` 누락 | key 추가 또는 `required = false` |
| `415` | POST/PUT 에 Content-Type 헤더 없음 | `-H "Content-Type: application/json"` |
| `405` | GET 으로 POST 주소 호출 (주소창은 GET만 보냄) | `curl -X POST` |
| `@Valid` 가 안 먹힘 | `starter-validation` 의존성 누락 | Step 1 의존성 추가 후 Gradle Reload |
| `JAVA_HOME is not set` (터미널) | 터미널에 JDK 경로 없음 | IntelliJ 안에서 실행하거나 `JAVA_HOME` 설정 |
| 주석 URL 을 복사했는데 404 | **주석은 근거가 아님**, 애너테이션 값으로 주소를 조합 | ① ② 단계로 점검 |
| 재시작하니 회원이 사라짐 | 메모리 저장소 (정상) | DB 단계에서 해결 |

## 도전 과제

1. **`GET /api/v1/members?organization=kyobo`** — query 로 목록 필터링 (`@RequestParam(required = false)`).
2. **중복 이메일 → `409 Conflict`** — `DuplicateEmailException` + `ApiExceptionHandler` 에 핸들러 추가.
3. **모든 검증 오류 메시지 반환** — 지금은 첫 메시지만 반환한다. `ErrorResponse` 를 `List<String>` 으로 확장.
4. **React 연동** — Day02 의 `App.jsx` 에서 `fetch('/api/v1/members')` 로 목록 표시, 등록 폼 추가 (`@CrossOrigin` 필요).
5. **강의 원본 비교** — `PutController` / `DeleteController` 는 저장소가 없었다. 어떤 코드를 바꾸면 `MemberController` 와 같은 모양이 되는지 정리해 보기.
